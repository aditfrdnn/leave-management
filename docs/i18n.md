# i18n — English and Indonesian

The app speaks English (`en`, default) and Indonesian (`id`) through [next-intl](https://next-intl.dev).
The language lives in the `NEXT_LOCALE` cookie, never in the URL: routes stay the same in both languages.
A first visit with an Indonesian browser gets Indonesian; the header's language menu changes it.

## Where things are

| What | Where |
| --- | --- |
| Locales, default, cookie name | `src/i18n/config.ts` |
| Per-request locale and messages | `src/i18n/request.ts` |
| Namespace registry and types | `src/i18n/messages.ts` |
| Messages | `src/messages/<locale>/<namespace>.json` |
| Language menu | `src/components/common/language-switcher.tsx` |
| Parity check | `node scripts/check-messages.mjs` |

One namespace per module, matching the module registry (`src/constants/app-module-constant.ts`):

| Namespace | Owns |
| --- | --- |
| `common` | Shared words (actions, states, generic validation) and shared components in `src/components` |
| `nav` | Module and menu names, breadcrumb segment labels, the brand name |
| `auth` | Sign-in page and layout |
| `leave` | Leave requests: form, history, statuses, validation |

A new namespace needs its two JSON files plus an import in `src/i18n/messages.ts`.

## Writing translated code

- **Client and sync server components:** `const t = useTranslations("leave")`, then `t("title")`.
- **Async server components, server actions, `generateMetadata`:** `const t = await getTranslations("leave")` from `next-intl/server`.
- **Interpolation and plurals:** ICU syntax. `"selected": "{count, plural, one {# tag} other {# tags}}"`, then `t("selected", { count })`. Never build sentences by concatenating translated pieces.
- **Rich text:** `t.rich("hint", { b: (chunks) => <b>{chunks}</b> })` with `"hint": "Use <b>Generate</b> to start"`.
- **Labels in module-level constants** (status maps, select options, column definitions outside a component): store a message key in the constant and translate where it renders. Constants must not call hooks.
- **Zod messages:** use the full message key as the message, e.g. `z.string().min(1, "leave.validation.subjectRequired")`. `FormMessage` and `FieldError` translate keys automatically; anywhere else that shows a validation message, use `useTranslateMessage()`. Generic cases can use `common.validation.*`.
- **Toasts:** translate at the call site: `toast.success(t("toast.saved"))`.
- **Dates:** `format(date, "dd MMM yyyy", { locale: useDateLocale() })`. Numbers: `useFormatter().number(value)`.
- **Key names:** camelCase, grouped by page or feature (`leave.form.fields.days`). Keys must not contain dots.

Run `node scripts/check-messages.mjs` before committing: every key must exist in both languages.
If a translation is missing at runtime, English is shown instead.

## What is not translated

- Data from the backend or typed by users: LVR numbers, reasons, locations, names of approvers and replacements, leave type names.
- Backend messages (API validation errors, toast text returned by Laravel). The frontend already
  sends `X-Locale`; the API answers in English until the item in `docs/backend-task.md` is done.
- Code, IDs, enum values sent to the API.

## Indonesian style

- Semi-formal, short, verb first: "Simpan perubahan", "Unggah file". Use "Anda" only when a pronoun is unavoidable.
- No "silakan" or "mohon" on buttons and labels; they are fine in longer help text.
- Sentence case, like the English.

## Glossary

Engineering and product terms stay in English in Indonesian text, because that is how the
teams say them. Generic UI words are translated.

| Keep in English | Translate |
| --- | --- |
| LVR, Approver, Lead, Supervisor, leave type names as the API sends them | Save → Simpan, Cancel → Batal, Submit → Kirim, Leave → Cuti, Leave Request → Pengajuan Cuti, Pending → Menunggu, Approved → Disetujui, Rejected → Ditolak, Reason → Alasan, Replacement → Pengganti |
